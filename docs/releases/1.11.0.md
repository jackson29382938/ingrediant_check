# Ingredient Check 1.11.0 — purchase history and trends

Setup can now open Amazon.com Orders for a guided first-page import, using the user's goals and
warning preferences. Actual order items receive rating snapshots; viewed products and carts never
create purchases. Open additional order pages/year filters to extend history. Saved ratings/labels are reused before public lookups. Revisits deduplicate,
completed returns/cancellations leave trends, and missing labels remain unscored. Monthly averages
separate scoring setups and versions. Snapshots use current available labels, not reconstructed
historical package labels. The first version holds 1,000 distinct order/product entries.

Purchase history has automatic Google-account sync with Sync now, offline retries, export and
confirmed local/account deletion. Separate authenticated backend rows enforce account isolation;
reset epochs prevent stale devices from restoring deleted history. No addresses, payment details,
prices or raw order numbers are stored/uploaded. Public label requests omit cookies and referrers.
Settings backups/imports cannot enable or carry purchase history.

**Backend deployment is still required.** The owner-supplied Apps Script project is identified in
[deployment instructions](../PURCHASE-HISTORY.md#backend-deployment-required), and the complete
server update is [apps-script.gs](../apps-script.gs). This cloud environment lacks authenticated
Apps Script deployment access. The live endpoint currently has settings accounts but no history
capability. Until deployed, imports/trends work locally and sync reports backend update required
before sending any private history data. No live signed-in Amazon order account was available.

Validation: 1,039 Node tests, zero-warning lint, preflight, packaging and the complete unpacked Chrome
harness, including first/older order pages, missing labels, returns, purchase-only trends, automatic
and manual sync, offline retention and deletion. OAuth/history backend calls use controlled fixtures.

Update files in the existing extension folder, Reload at chrome://extensions, and refresh store
tabs. Run setup again to enable purchase history; it is off until selected.
