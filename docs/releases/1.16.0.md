# Ingredient Check 1.16.0 — quantities, allergen lines and cleaner text

A review of the whole scoring path found places where the engine threw away information a label
prints, and places where a harmless difference in punctuation made a charged ingredient disappear.
This release fixes them. `RULES_REVISION` is `2026-10-18.1`, so every cached score is retired.

## What changed in scoring

**A declared quantity now sets an ingredient's weight.** Position is only a proxy for how much of a
product something is, and the engine kept the proxy while discarding the real number. `Oats 98%,
Sugar 2%` scored exactly like `Oats 60%, Sugar 40%`. A share written in front of, after or in
brackets beside an ingredient (`Hazelnuts (13%)`, `Zucker 45 %`, `Sugar max. 40%`) now picks one of
the same four weights list positions use: 25% or more weighs 1.5, 10% or more 1.25, 2% or more 1,
and under 2% 0.5. Sub-ingredients take their parent's share. Lists with no declared quantities
score exactly as before.

**"Contains 2% or less of…" is read as what it says.** It used to become a plain comma, so trace
ingredients kept the weight of their list position. Everything after that marker now weighs as a
minor ingredient. Only a limit of two percent or less opens the block; "less than 5%" stays a
separator, and a marker inside brackets cannot demote the rest of the list. Two corpus products
move: chicken broth 33 → 45 and deli turkey 32 → 40 (flavouring and yeast extract under 2%). Every
other calibration entry is unchanged.

**The label's allergen line is no longer scored as ingredients.** `CONTAINS: MILK, SOY.` read as two
unrecognised ingredients, which made `Oats, Honey` NOVA 3 and 15 points lower. A line that begins
with *Contains* or *Allergens* and names only allergens (or "none") is now set aside from scoring,
under English, Spanish, Italian, French, German, Portuguese, Dutch, Swedish and Polish headings. It
still raises allergen flags and still matches the avoid list. "Contains: sugar, salt" is a list and
still scores as one.

**Separators no longer hide ingredients.** Each of these glued two ingredients into one entry no
rule could read, so the charge silently disappeared (`Oats, Sugar` scores 65; the variants scored 90):
`Sugar - 20%`, `Sugar: 20%`, `Sugar = 20%`, full-width and Arabic commas, bullets, pipes and middle
dots, zero-width characters and soft hyphens, HTML tags and entities, and "…of the following: sugar"
lead-ins. A line wrapped inside one ingredient is still one ingredient.

**More plain foods are recognised.** Shallots, okra, blackberries, bulgur, flaxseed and dozens of
similar words matched no rule and no vocabulary entry, so a short list of them could fall
under the coverage gate and show no score. Nothing here is charged.

## One readability gate

Eight call sites each kept their own copy of the 0.34 coverage threshold, and a list with no entries
scored 90 "Excellent" because every "all culinary" test passes vacuously. The engine now owns the
number (`MIN_COVERAGE`), returns `readable` on every result, and exports `isReadable()`. Every
pipeline (product page, search tiles, retailer search, cart, order history, purchase analytics)
asks that one question. An empty or unreadable list is never readable.

## Interface fixes

A screenshot pass over every extension page and the score panel, in light and dark at desktop and
phone width, found four defects that the automated contrast and layout checks did not:

- **Score panel, dark theme.** "How this was produced" inherited black text for each certification and
  a light-theme grey for its description, so grass-fed and organic claims read as black on near-black.
  They now use light text, and the tick colours are lifted to match.
- **Popup.** "Purchase history & trends" sat flush against the left edge, underlined, while the link above
  it was indented. It now shares the row of links with "Access and what is sent".
- **Report a problem.** Checkboxes and the file picker used the browser's default blue and grey. They take the
  brand colour, and the "Choose File" button is styled like the page's other buttons. An unticked
  part's settings preview was faded to about 3:1 contrast; only the preview dims now, and the note under
  it keeps full contrast. The same brand colour now applies to checkboxes and radios on the purchase
  history page.
- **Setup.** The step heading takes focus on each step so a screen reader announces it, and showed a heavy
  black box around the title. It is not a control, so it no longer draws a ring.

## Tests and CI

`tests/invariants.test.js` states the engine's properties for any input rather than for pinned
lists: scores are integers on the published scale for every preset, scoring is deterministic and
does not mutate its input, adding or promoting a penalised ingredient never raises a score, a
declared quantity outranks position, no generated text can crash scoring, and unreadable text is
never readable. The suite is 1,125 tests.

CI now also runs Node 24, cancels runs a newer push supersedes, uses read-only permissions and has
job timeouts. The scoring inventory is regenerated from the rule tables; it had drifted from the
defaults it describes.

Chrome users: update the files in the existing install folder and Reload, which keeps the extension
ID and local data. Firefox users: upload `ingredient-check-1.16.0-firefox.zip`.
