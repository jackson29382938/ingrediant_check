# Ingredient Check 1.11.4 — faster order ratings and complete label fallbacks

Orders paint all saved ratings before public product requests, with one batch cache read. A
product is fetched once per page even when bought in multiple orders; fresh product readings
are saved locally for reuse. Scores saved by opening a product update an open Orders tab
automatically. First purchase snapshots remain preserved.

Missing text labels now use the same optional barcode/Open Food Facts and on-device label-photo
OCR paths as product pages. OCR is processed separately from the paced product fetches so it
cannot hold every product-page request behind a slow image. History settings expose Read label
photos, barcode lookup and the existing 2–5 concurrent request pace. Permission/toggle checks,
request budgets, cookie/referrer omission and challenge stops remain enforced.

Image-only order badges sit within their thumbnail instead of extending into the next fixed-height
grid row or order header. Text-title badges stay beside their titles.

Validation: 1,054 Node tests, zero-warning lint, preflight, packaging and unpacked Chrome checks.
Browser coverage includes cached ratings before a deliberately held request, automatic cache updates,
thumbnail badge bounds, barcode/OCR routing and disabled controls, source-correct local caching,
first snapshots, history/sync regression checks and actual vendored OCR on a generated readable
label. Signed-in live orders and every package photo remain unverified. OCR requires legible
ingredient text, can take longer than cache/text, and does not guess nutrition numbers.

Reload the updated extension and refresh Orders. Open History & sync settings to find the label
reading controls and select Fast for the maximum supported product-fetch pace.
