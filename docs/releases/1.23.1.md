# 1.23.1

- **The sorted list now works on every supported store**, the way it does on Amazon: Walmart, Target, Costco, Instacart,
  Kroger, Fry's, Ralphs, King Soopers, Smith's, Fred Meyer, QFC, Harris Teeter, Dillons, Safeway and Albertsons. Each
  search page gets an **Ingredient Check sort** button with Amazon's two entries and wording (*Ingredient Check score:
  High to Low*, *Price per ounce: Low to High*, in the unit most listings state). Choosing one opens the same side-panel
  list as Amazon's: Prioritize sliders, the unit picker, Stop, Back to search, and **hovering a score shows why it
  scored that way**. The keyboard shortcuts work on these searches, and an open list follows a new search.
- The list is built as on Amazon, under the same settings: this page's listings with saved scores first; then, with
  **Load more results** on, further result pages up to **Products to compare** and the time limit; then, with **Rate
  them**, the product pages of what is still unscored. A store's pages are read from their HTML, or, where the HTML holds
  no results (Target, Instacart, the Kroger banners), from a hidden frame; a store with no next-page address is scrolled
  for you and put back. See `docs/PRIVACY.md` for exactly what each does.
- This replaces Walmart's 1.21.0 "Price & health" drawer. Settings, popup and shortcut descriptions no longer say
  "Amazon" where they now apply to every store.
- Fix: **the extension did not run for a search started from the Walmart or Target home page.** Both sites change the
  address without loading a page, and the script was injected only on results and product pages, so a search typed
  into the header got no ratings, no sort and every advertisement. It now also loads on the public home and
  category/browse routes (see `docs/PRIVACY.md`); account, cart, checkout and login pages stay out.
- Fix: **Walmart sponsored results were not always hidden.** A banner marked only by its "Sponsored" label and an ad
  whose only link is Walmart's ad tracker were missed even after a reload. Ads are now recognised by any of several
  independent signals (ad-tracker link, placement attribute, accessible name ending in "Sponsored", the label itself),
  hidden as the outermost wrapper that holds only that ad, and never rated or fetched. Ads that arrive after load are
  hidden on the next frame; organic results, the grid and the page are never hidden. Pausing restores every ad.
- Fix: with the list open, "Follow new searches" now works for a store (the worker used to ask the browser for the
  tab's address, which it does not give for a store the extension holds no site permission for).
- Hidden-ad bookkeeping no longer un-hides and re-hides every ad on each pass; a full pass on a 221-card page costs
  about a quarter of what it did.
- Target: advertisements are marked *Sponsored* in the list (they are not hidden).
- Scores, scoring rules and `RULES_REVISION` are unchanged.

Known limits: Walmart's and Target's live search pages could not be captured (Walmart's bot check, Target HTTP 429); the
browser checks use replica pages built from earlier recordings. For the other thirteen stores only the shared path and
the registry/adapter agreement are covered, so **their live pagination is unverified**. See `docs/STORES.md`.

Validation: unit tests (`tests/walmart-sponsored.test.js`, `tests/retailer-sort.test.js`,
`tests/retailer-sort-all-stores.test.js`, `tests/sort.test.js`), preflight, ESLint, and `npm run retailers:check`, which
drives the real unpacked extension through search-from-home, ad hiding, the menu, the list through the real worker
(pages 2 and 3, the count cap, scrolling, hover notes, Follow, the keyboard shortcut), the cart and a phone width, with
screenshots in `docs/screenshots/retailers/`.
