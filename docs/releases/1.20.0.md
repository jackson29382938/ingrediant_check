# Ingredient Check 1.20.0

A review-driven release: three bugs fixed, automatic rating made consent-first, and the plumbing around it
(navigation, storage, packaging, the shared backend) made cheaper and safer. No scoring rule changed: the rules
revision stays `2026-10-30.2` and every corpus product keeps its band.

## Fixed

- **The side panel crashed on supplement and personal-care searches.** `sidepanel.html` did not load
  `product-ratings.js`, so the first personal-care row in a sorted list threw and the list stopped rendering.
  A new test (`tests/page-dependencies.test.js`) reads every extension page, every content-script group and the
  service worker and fails when a script uses a module its surface does not load.
- **An Amazon robot check answered with HTTP 200 was read as "no readable ingredients".** The tile and sort
  readers now recognise the challenge page, stop for the rest of the results page, record nothing for it, and tell
  the other tabs to wait.
- **"Report a problem" told people to set a contribution URL that no longer exists.** A failed send now says it
  could not send and leaves the link usable to try again.
- The popup status request (`diagnosticsStatus`) now always answers, like every other worker message.

## Automatic rating asks first

- Nothing is requested from Amazon until the first-use notice is answered. **Rate these results** starts the
  requests; **Turn off automatic rating** switches the setting off. Saved scores show either way, and a hover is
  still the reader's own request. Finishing setup with the option ticked is also an answer (the setup page now
  says what it requests, signed in as you).
- One request allowance for the whole browser (300 per ten minutes) instead of one per tab, and a cool-down after a
  robot check or five refusals (15 minutes, doubling to four hours). Both live in the service worker's session
  storage and reset when the browser closes.
- A status line above the results: how many are scored, the best score with **Show best**, **Pause / Resume**, and
  why requests are waiting when the allowance or a cool-down is holding them.

## Cheaper in the background

- **One navigation watcher.** `src/content/nav.js` replaces four timers (500 ms and 1 s) that polled
  `location.href` on every store tab for as long as it lived. With the Navigation API (every supported Chrome) it
  reacts to history changes and keeps only a five-second safety check; Firefox without the API polls as before.
- **Product pages stop being observed once they are quiet.** After 60 seconds with no change to the reading the
  observer stops; a click or a scroll (Amazon builds lower sections as they come into view) starts it again.
  Results pages are never timed out.
- **Purchase history is stored in 64 buckets plus an index** (`src/engine/db/purchase-store.js`). Measured in
  Chromium with 8.3 MB of history: adding one record took 2.7 s as one key and 72 ms as a bucket, and every tab
  stopped receiving the whole history in each `storage.onChanged` event. An existing single-key history is read as
  before and moved on its next write.
- The scoring engine is warmed up on cart and order pages too, as it already was on product and results pages.

## Safer

- The manifest's Amazon patterns are `https://*.amazon.<tld>/…`, one per path. Probed in Chromium: the wildcard
  matches the bare domain as well, so the 336 apex duplicates are gone (672 patterns became 336).
- Extension pages and the service worker may connect only to the five hosts the code talks to
  (`connect-src`: Apps Script, its answer host, Open Food Facts, Google's profile endpoint, Amazon's image host);
  a test ties that list to the code.
- The worker bounds what a content script hands it before it queues or posts it: reports, contributions, diagnostics
  rows and certification lookups.
- Release workflow: the validation job is read-only and only the publishing job can write; tool installs skip
  install scripts; Dependabot watches the action versions.

## Shared backend (redeploy `docs/apps-script.gs` by hand)

- Anonymous writes (diagnostics, reports, contributions, product rows) share a per-minute allowance and the three
  tabs they write to keep a rolling window of rows, so a flood cannot fill the spreadsheet that also holds accounts
  and purchase history. Signed-in kinds are not counted.
- `weeklyDriftReport()` mails the owner when the share of unreadable pages rises, overall or for one store
  (`installDriftTrigger()` schedules it). See [SETTINGS-SYNC.md](../SETTINGS-SYNC.md).

## Tooling

- Packaging is plain Node (`scripts/zip.mjs`): no python3, and two builds of one commit now have the same
  SHA256 (entries sorted, fixed timestamps).
- `npm run test:coverage` prints line, branch and function coverage from `node:test`, with no dependency.
- ESLint gets a line-length ratchet: 300 characters for every `src` file not on the (shrinking) legacy list.
- `scripts/script-lists.mjs` is the one place content-script lists are written; preflight fails when
  `manifest.json` differs.
- The German interface catalog is removed; English is the only UI language. Reading German (and other) ingredient
  lists is scoring behaviour and is unchanged.

## Not changed

Moving accounts and purchase history off the shared spreadsheet, switching Google sign-in away from the implicit
flow, and publishing to the Chrome Web Store and AMO need decisions and credentials outside this repository. They
are listed in the review that preceded this release.
