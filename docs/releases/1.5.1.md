# Ingredient Check 1.5.1

Fixes found by five parallel audits across Amazon, Target, Walmart, Costco and setup reliability.

- Amazon reads full Nutrition Facts alongside summary values and refreshes scores after long ingredient tails or nutrition text changes.
- Target handles serving-size units and conflicting panels conservatively; ingredients and search badges stay tied to their product identity.
- Walmart recovers visible labels when embedded declarations are empty, decodes label entities, and rejects malformed identity or oversized labels.
- Costco excludes navigation promotions, handles image-only cards and rejects ambiguous product cards.
- All retailer previews update scores after label hydration, reject recommendation/oversized/unparsed labels, and remove stale saved scores when changed data cannot be scored.
- Setup blocks overlapping navigation/sign-in/save operations, confirms local storage before backup, handles Skip failures and clears earlier account tokens before retries. OAuth response validation is stricter.

Validation: all 703 Node tests, ESLint, preflight, packaging and Chromium harness, including late ingredient changes on Target, Walmart and Costco. Public GET checks succeeded for Amazon and all three previews; full live-browser retailer validation remains incomplete. See [parallel audit](../PARALLEL-AUDIT-2026-10-04.md).

Google’s OAuth redirect registration remains external: this environment has no authenticated Google Console management access. No new permissions or data collection were added.
