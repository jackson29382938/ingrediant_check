# 1.24.0

- **Pick how many products to compare from the list itself.** The sorted list (Amazon and every other store) has a
  **Compare up to … products, for up to …** row above *Prioritize*. Type a count from 1 to 500 (300, say), choose how
  long it may take, and press **Update list**: it saves them, turns *Load more results* on, and runs the same search
  again, reading further results pages until it has that many or the time is up. It is the same setting as Settings,
  Sort, so nothing has to be changed in two places. The default time limit is 60 seconds, which a long list will
  usually outgrow, so pick a longer one. The page cap behind the count rose from 30 to 60 results pages on the other
  stores, so a count of 500 is not cut short.
- **Saved scores load faster on the other stores.** Walmart, Target, Costco, Instacart, Kroger and its banners, and
  the rest saved a score together with the label text it came from, but accepted it only while your weights and the
  scoring rules were exactly as they were when it was saved. After a change it was thrown away and the product page
  was downloaded again. Now the search badges and the sorted list score that saved label text again on your computer
  (about a millisecond each) and keep the result, with the age of the label it came from. Nothing is requested.
- **A product you have opened before answers at once on those stores' product pages.** Until now the extension waited
  for the store to draw the label, or showed "Open Label info" when the store hides it. It now shows the saved score
  while the page has no label; the label on the page replaces it the moment it appears and is never overridden.
- **Amazon same-day grocery searches: cards with unfamiliar markup are found.** A card whose title is plain text in a
  link to its own product (no heading, none of the title classes this code knew), or whose ASIN appears only as
  `data-csa-c-item-id`, used to be skipped as if it were not a result, so the page showed no badges and the list was
  empty. Both are now listings. A card in a carousel that only links to a product still is not one. When a results page
  still has no listing five seconds in, "Report a problem" lists counts of what the page does have.
- Scores, scoring rules and `RULES_REVISION` are unchanged.

Known limits: **the same-day grocery change is not verified against the live page.** Amazon returns an error page to
automated requests (a 503 for the bacon search), so its real markup could not be captured; the fix is written to cope
with the layouts it could think of and tested on two synthetic ones. If a same-day search still shows nothing, the
"no listing recognised" line in Report a problem says what the page contains. Reuse of a saved reading does not apply to
Amazon, which already re-scored from its saved reading, and a listing with no ingredient list is still requested again
after a settings change.

Validation: unit tests (`tests/score-cache.test.js`, `tests/retailer-search.test.js`, `tests/target.test.js`,
`tests/background.test.js`, `tests/listing-title.test.js`), preflight, ESLint, the Chromium harness (including two
synthetic same-day layouts) and `npm run retailers:check`, which gains a weight-change scenario (21 saved Walmart
listings come back with no product page requested; 12 of 21 when the re-scoring is switched off) and a "Compare up to"
scenario run through the real worker.
