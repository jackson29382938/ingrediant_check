# 1.22.0

- Purchase history opens with insights instead of a full screen of scan instructions. Import/scan controls remain available in a disclosure and through navigation links.
- A visible coverage summary explains missing scores, excluded purchase statuses, approximate ingredient-only comparisons, and mixed recorded scoring setups. These are purchase ingredient scores, not measurements of the user's health or consumption.
- Recorded timeline series distinguish scoring-rule revisions as well as app versions and preference profiles. Original saved records remain untouched; current-goal comparisons still use a single current setup.
- The open dashboard evicts cached scoring inputs when their history entries are removed or replaced. Deleted label text no longer remains in that scoring cache until preferences change or the tab closes.
- Clear empty-history and no-filter-match states help users recover without implying that data was lost. Desktop and narrow dark layouts are checked with synthetic records in an isolated browser context.
- Apply the saved theme and accent to the whole history page, including native controls, using the shared appearance pipeline.

Validation: full Node regression suite, `HARNESS_CHROME=/path/to/chromium npm run history:check`, preflight, browser packaging and Firefox package lint. The browser check verifies immutable snapshots, scoring-cache eviction after deletion/reimport, coverage explanations, current-goal comparison and mobile layout. No real user account was accessed or changed.
