# Ingredient Check 1.5.0

Google sign-in is now an optional fifth setup step. Setup shows and copies the installed extension’s OAuth redirect URL before identity permission is granted. Choices save locally before account backup; cancelled sign-in or failed backup leaves setup usable, and access tokens are never persisted. The worker allows onboarding to save a backup, while restore and other settings actions remain restricted to Settings.

Walmart and Costco join Target as previews. Walmart reads the current product’s embedded ingredient declaration after checking its ID; Costco reads visible labels and offers paste fallback. All previews read only pages you open, keep scores locally, and show saved scores on searches. They never fetch other retailer products. Target now rejects stale canonical product labels and reads declared trans fat. Product IDs reject foreign hosts, and reports exclude private retailer routes.

Normal public requests returned HTTP 200 for all three retailers on October 4. Walmart exposed a usable declaration; initial Target and Costco HTML did not. Complete live-browser retailer validation remains pending, so preview labels stay explicit.

Google Cloud must authorize the exact redirect URI reported by the installed extension. For the owner’s reported installation: `https://kimgmdjgfaoccgibnpklgcgillegenpd.chromiumapp.org/`. This release cannot register that URI or deploy the account backend without authenticated Google management access. See [Google setup](../GOOGLE-SIGN-IN-SETUP.md).

Validation: full Node test suite, ESLint, preflight, extension packaging, and Chromium harness covering setup, account backup handling, retailer product scores, toolbar badges and saved-score search badges. Retailer browser scenarios use intercepted fixtures; they are not a claim of complete live-site support.
