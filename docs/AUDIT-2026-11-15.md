# Improvement audit — 2026-11-15

Reviewed `main` at **`739f3cb`**, extension **1.26.3**. This is an audit, not an implementation
change: nothing in `src/` was edited. Priorities give the recommended order of work:
**P1** = a score or warning the shopper sees is wrong; **P2** = release safety or a worker failure;
**P3** = follow-up improvement.

The main result: every automated check passes, and the code around privacy, messaging and the
backend is careful. The scoring parser still has six label formats that hide a charged ingredient,
two of them common on US labels. They are the first thing to fix.

Every P1 finding is reproduced by `node docs/audit-verification-2026-11-15.cjs` (30 of 30 checks
reproduce on this commit; a fixed finding prints "fixed").

## P1 — a charged ingredient goes unread

`CLAUDE.md` states the rule: nothing is charged that no rule matches, so a format the parser does
not understand quietly scores better. Each finding below is such a format. In every case the list
still reads as readable, so the shopper sees a confident number.

Each fix moves scores, so each needs a `RULES_REVISION` bump, the format added to
`tests/invariants.test.js`, and a release note.

### 1. "X and Y" is not split when any rule reads X

`splitConjunction` (`src/engine/score.js:671`) keeps the pair whole if any penalty rule matches the
joined text. That test was meant for rules that read the pair as one thing ("mono- and
diglycerides"). It also fires when an unanchored rule matches only one half, and the other half is
then never charged.

| Label | Scores | Written with a comma |
|---|---|---|
| `Roasted peanuts and sugar, salt` (the opening of a common US peanut butter label) | 80 | 65 |
| `Wheat flour and sugar` | 75 | 54 |
| `Water, citric acid and sugar` | 74 | 61 |
| `Nonfat milk and dextrose` | 96 | 65 |

In a sample of 2,280 pairs built from fixture ingredient names and five sweeteners, 883 scored at
least five points higher joined than separated. The sample includes some strings that are not
ingredients, so read the figure as indicative.

**Fix:** split when every piece is recognised and the pieces together are charged more than the
whole (`chargeOf`), the same test `rejoinWrapped` and `apart` already use. "Mono- and diglycerides"
and "natural and artificial flavors" stay whole under that test, because splitting them charges
nothing more.

### 2. "and" before the last ingredient

`Milk, cream, and cane sugar` scores 90; without the "and" it scores 65. The entry arrives as
"and cane sugar" and rules anchored at the start of an entry do not read it. Of 632 charged
ingredient names, 154 lose their charge this way (the sugars, mostly). The same 154 are lost after
`&`, "with", "including", "added" and "also".

**Fix:** drop a leading conjunction in `tidy`, in the store languages, as a leading share and a
leading heading are already dropped.

### 3. Typographic hyphens

`high‑fructose corn syrup` written with a non-breaking hyphen (U+2011) scores 90 against 30 for the
ASCII hyphen: the cap is lost and coverage still reads 100%. `glucose–fructose syrup` with an en
dash does the same. Web pages use both characters.

**Fix:** in `cleanText`, map U+2010, U+2011 and U+2012 to `-`, and an en dash between two letters
with no spaces to `-`.

### 4. Footnote marks the parser does not strip

`MARKERS` (`score.js:409`) covers `* ° ¹ ² ³ † ‡ # ® ™`. Labels also use:

| Written | Scores | Plain |
|---|---|---|
| `Oats, cane sugar1, salt` (a superscript flattened by `textContent`) | 90 | 65 |
| `Oats, cane sugar<sup>1</sup>, salt` (the tag becomes a space: "cane sugar 1") | 90 | 65 |
| `Oats, cane sugar+, salt`, and `^` `§` `◊` `∆` `ª` | 90 | 65 |

A trailing digit hides 404 of the 632 charged names; each of the other marks hides 152.

**Fix:** add `+ ^ § ◊ ∆ ª` to `MARKERS`. For a digit, drop one trailing digit (with or without a
space) only when the rulebase then charges more, so "Red 40", "Polysorbate 80" and "vitamin B12"
keep theirs.

### 5. Text in angle brackets is removed as an HTML tag

`HTML_TAG` (`score.js:959`) removes anything shaped like `<word …>`. `Oats, <red 40>, salt` scores
94 with 100% coverage; the plain list scores 18. All but 19 of the 632 names vanish this way.
Angle brackets round an ingredient are rare on labels, which is why this is below findings 1 to 4.

**Fix:** remove only real HTML element names; turn any other `<…>` into parentheses.

### 6. "Less than" written with a sign, or without "of"

`Oats, <2% sugar, salt` scores 90 (the bracketed form `sugar (<2%)` scores 68).
`Oats, less than 2%: sugar, salt` scores 90 (with "of" it scores 73). `LEADING_SHARE` does not
accept `<`, and the minor-ingredient marker requires the word "of".

**Fix:** accept `[<≤]` in `LEADING_SHARE`, and a colon in place of "of" in the marker pattern in
`parseEntries`.

## P1 — allergen warnings

### 7. Missed and false allergen matches

The popup says the flags are not allergy advice, and a miss here still matters more than a wrong
score. Of 424 synonyms tried, most are caught. The misses worth fixing:

| Allergen | Not flagged |
|---|---|
| Wheat / gluten | bare `flour`, `enriched flour`, `all-purpose flour`, `cake flour` (in the US, unqualified flour is wheat flour), `udon`, `pasta`, `noodles`, `cracker meal`, `atta`, `maida` |
| Tree nuts | `filberts`, `chestnuts`, `pignoli` |
| Fish | `flounder`, `sole`, `bass`, `isinglass`, `nam pla` |
| Milk | `caseinates` (the plural), `lactoferrin`, `natural butter flavor` |
| Shellfish | `langostino`, `barnacle`, `geoduck`; `glucosamine` and `chitosan` on supplement labels |
| Sesame | `tehina`, `til`, `sim sim` |
| Soy | `okara`, `kinako`, `bean curd` |
| Egg | `ovomucoid`, `ovotransferrin`, `vitellin`, `livetin` |
| Sulfites | `sulphiting agents` |

False alarms: `butter beans` and `cream of coconut` (milk), `oyster mushrooms` and `scallop squash`
(shellfish), `gluten-free oats` and `wheat-free tamari` (wheat), `egg-free noodles` (egg).

**Fix:** add the words to `src/engine/db/allergens.js` and the pairs above to
`tests/synonyms.test.js`. Flags do not move a score, but `allergens.js` is hashed, so the revision
still needs a bump.

## P2 — release safety and the worker

### 8. The release job installs unpinned packages while holding a write token

`.github/workflows/release.yml` pins every action to a commit, for the reason its comment gives.
The same job then runs `npm install --no-save --no-package-lock web-ext@10.0.0`. Only the top
package is pinned: its roughly 340 dependencies resolve fresh on each run, their install scripts
run, and the next step publishes `dist/*.zip` with `contents: write`. `npm audit` reports 11
advisories in that tree today (3 critical). A compromised transitive package could alter the zip
before it is hashed and uploaded.

**Fix:** hash the packages straight after `npm run pack`, before any install; run the Firefox lint
in the read-only `validate` job; and install tools with a committed lockfile and
`npm ci --ignore-scripts`.

### 9. The AI request allows 40 seconds; Chrome allows a worker fetch 30

`src/worker/ai.js` sets `TIMEOUT_MS = 40000`. Chrome's documented service-worker lifecycle ends a
worker whose `fetch()` has had no response for 30 seconds. A slow free vision model would then end
the worker with no reply to the page, and the in-memory rate-limit pause would be lost. This is
from Chrome's documentation; it was not reproduced here.

**Fix:** set the timeout below 30 seconds so the request fails through the handled path.

## P3 — follow-up

### 10. Accessibility

axe-core found two serious and four moderate issues; four of the eight pages are clean in
both schemes, and no page overflows at 360 px.

- `report.html`: `#settingsPreview` scrolls but cannot be reached by keyboard. Add `tabindex="0"`
  and a label.
- `history.html`, dark scheme: the two links in `#historyEmpty` differ from the text around them by
  colour alone (2.06:1). Underline them.
- `popup.html` has no `main` landmark; `options.html` leaves the search tools outside any landmark;
  `history.html` nests its `aside` inside another landmark.

### 11. Every matched Amazon page loads 871 KB of script

Forty files are injected at `document_idle` on each matched page, including the home page and deal
pages: the whole engine (107 KB), DOMPurify (84 KB, needed only when a panel is drawn) and the sort
and cart scripts. Loading the sanitizer and panel on first use would cut what an ordinary page pays.
This is a measurement of size, not of time.

### 12. A long hyphenated run takes a second

`spaced()` (`score.js:283`) is recomputed for every rule when an entry is too long for the lookup
memo. 40,000 characters of `a-a-a-…` take about 1,000 ms; growth is linear. No label is that long,
but a hostile page can be. Compute it once per entry.

### 13. Worker state kept only in memory

The AI rate-limit pause (`backoffUntil`) and the shared-products back-off are lost each time the
worker stops, so a 429 with a long `Retry-After` is forgotten after 30 idle seconds. Keeping them
in `chrome.storage.session` would hold them. Separately, the sorted-list page reconnects its port
one second after it drops (`sorted.js:733`), which may wake the worker every half minute while the
list is open; a debugger keeps the worker alive, so this could not be confirmed here.

### 14. Two formats that fail safely

- A list headed "Contains:" whose every item names an allergen (`Contains: Milk, Wheat Flour,
  Soybean Oil, Eggs`) is read as an allergen statement and reported unreadable. No wrong score is
  shown; the product just goes unrated.
- A two-line list (`Oats\nSugar`) is read as one wrapped ingredient and scores 90. This is the
  documented choice; the "charges more" test used for dashed lists would settle it.

## What is in good order

- The message allow-list checks sender, frame and page for every type, and network paths are
  limited to the worker.
- Both API keys stay out of backups, exports and reports. No project key is in the repository.
- The backend verifies Google tokens before taking its lock, checks the audience, quotes
  formula-leading cells and caps anonymous writes.
- Sheet data is indexed on null-prototype maps, and unknown message types are refused.
- Sharing, diagnostics and AI are off by default; the popup states what auto-rating requests.
- The interface renders cleanly at phone and desktop widths in both schemes.
