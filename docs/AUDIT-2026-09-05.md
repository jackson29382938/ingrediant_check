# Reliability audit — September 5, 2026

## Changes

The existing scoring, extraction, search-gating, nutrition, corpus, and arithmetic suites passed before changes. The principal newly reproduced defects were in background service behavior, which had no dedicated test suite.

- Serialize diagnostics appends and flushes to prevent lost rows when tabs submit concurrently or a new row arrives during a POST.
- Respect both the diagnostics setting and master pause before collecting or sending queued diagnostics.
- Require the receiving endpoint's JSON acknowledgement (`ok: true` and the expected `wrote` count) before deleting sent rows. HTTP 200 alone can also represent an Apps Script error or login page.
- Bound diagnostic requests to 15 seconds so an unresponsive endpoint cannot indefinitely hold the queue.
- Only use stale spreadsheet data when its URL matches the currently configured source.
- Treat an empty producer spreadsheet as an empty registry instead of retaining old certifications.
- Normalize published Google Sheet links to their public CSV route, preserving the selected tab; reject non-Google URLs.
- Use own-property checks when looking up records in stored maps. Chrome storage may deserialize maps as ordinary objects, so a missing brand such as `constructor` must not return an inherited property.
- Release the offscreen creation promise after completion so the OCR document can be recreated after Chrome closes it.

## Verification

- Full `npm test` suite passes, including nine new background regression tests.
- All nine new tests fail against the original service-worker source and pass with the fixes.
- `npm run preflight` passes: manifest files, 21 store patterns, OCR assets, localization, and diagnostics column alignment.
- `git diff --check` passes.
- Browser panel harness: oats render as 97 Excellent; the details expand; capped chips render as 25 Poor; manual `Peanuts, salt` entry enables the Score button and renders 80 Good.
- Real vendored OCR browser harness: image fetch succeeds, the worker recognizes the label, and an ingredient block is recovered (reported confidence 67). This uses the shipped engine and a real Amazon label image.
- Browser lifecycle harness: master pause produces no panel, no extraction, and no observer; non-food produces the refusal panel with zero extraction calls and disconnects its observer. The food case scores after one extraction and disconnects its observer. All three remain quiet through 15 page mutations.

## Limits and follow-up verification

This is software reliability verification, not validation of the nutritional model or its scientific claims. Existing scoring rules and weights were preserved.

Browser tests use the repository's harness. They do not establish that every current Amazon store layout works. The installed extension's optional-permission dialogs and Chrome offscreen messaging still need an actual extension-session check. The OCR harness verifies the engine and image reading, while the regression test verifies background document recreation with mocked Chrome APIs.

No diagnostics or contributions were sent to an external sheet. Receiver acknowledgements were simulated in tests. A deployed Apps Script round-trip remains unverified. Retries can duplicate rows if the server writes a batch but its response is lost; this change prevents premature deletion but does not add server-side deduplication.
