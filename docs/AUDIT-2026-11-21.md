## Detailed Findings & Integration Specifications

### 1. Complete Retailer Consent & Shortlist Writer Integration (P1)
- **Context:** Working-tree changes removed `alwaysRateSearch` overrides for Walmart (`src/content/retailer.js`, `src/stores/walmart.js`) and routed shortlist writes through the service worker (`shortlistSave` / `shortlistRemove`), leaving 4 failing tests (`tests/sanity.test.js`, `tests/retailer-search.test.js`, `tests/shopping.test.js`).
- **Fix:**
  - Declare `var SHORTLIST_MESSAGE_TYPES = new Set(['shortlistSave', 'shortlistRemove'])` in `src/worker/messages.js` and include it in `tests/sanity.test.js`'s allowlist scraper so static checks match runtime enforcement.
  - Update `tests/retailer-search.test.js` and `tests/shopping.test.js` to assert the hardened consent behavior (Walmart honors `autoScoreSearch: false` and `speedMode` fetch budgets) and the serialized `AIR.db.shopping.write()` / `save()` contract.

### 2. Surface Word-Level OCR Uncertainty in Product Panel & Upload UI (P1)
- **Context:** `src/engine/db/ocr-text.js` extracts `uncertainWords()` and `src/content/product.js` passes `uncertain: meta.uncertain` into `AIR.panel.render()`, but `src/content/panel.js` ignores `meta.uncertain`.
- **Fix:** Render a clear warning notice in `panel.js` whenever `meta.uncertain` is non-empty, listing up to 6 uncertain words and reminding the shopper to verify the physical package (especially for allergens). In `library.js`, also pass `data.words` into `uncertainWords()` on uploaded photos and surface any uncertain words in `#checkStatus`.

### 3. Truthful `label-ai` Attribution Across All Views (P2)
- **Context:** `panel.js` `sourceLabel()` and `shopping.js` `sourceLabel()`/`describe()` do not handle `via === 'label-ai'`, causing AI-transcribed photos to render as `"Ingredients read from page (50% confidence)"` or `"Product page"`.
- **Fix:** Add explicit `label-ai` branches in `panel.js` (`srcAiPhoto`: `"AI transcription of a product photo"`) and `shopping.js` (`srcShortAiPhoto`: `"AI transcription of a product photo"`), translated in `_locales/en/messages.json` and `_locales/de/messages.json`, with a table-driven test covering every source type.

### 4. Block Raw Unsegmented OCR Fallback in Upload UI (P2)
- **Context:** `src/options/library.js` fell back to `ingredientsFromOcr(extracted) || extracted`, allowing garbled non-block OCR (e.g., French biscuit photo `7622210449283`) to be scored directly.
- **Fix:** Use `labelFromOcr(extracted)`. Populate `labelAdvisory` when an advisory block is detected. When no ingredient block is found, keep the raw text in `#labelText` for manual cleanup, mark the upload as requiring manual edit before scoring, and guide the user clearly in `#checkStatus`.

### 5. On-Device Chrome Built-in AI (`Prompt API` / Gemini Nano) Provider (Feature)
- **Reference:** [Prompt API](https://developer.chrome.com/docs/ai/prompt-api), [Built-in AI APIs](https://developer.chrome.com/docs/ai/built-in-apis), [Extensions and AI](https://developer.chrome.com/docs/extensions/ai).
- **Design:**
  - Add `aiProvider` (`'auto' | 'gemini-nano' | 'openrouter'`, default `'auto'`) in `src/engine/db/prefs.js` (`WORKFLOW_KEYS`).
  - In `src/worker/ai.js`, detect `globalThis.LanguageModel`, query `LanguageModel.availability({ expectedInputs: [{ type: 'text' }], expectedOutputs: [{ type: 'text' }] })`, and invoke `LanguageModel.create(...)` with identical options and `RATING_SYSTEM` for `aiRateIngredients`.
  - Tag `aiIngredientCache` entries with `provider: 'gemini-nano' | 'openrouter'` so cached classifications seamlessly carry across providers.
  - Add `aiNanoStatus` to `SETTINGS_MESSAGE_TYPES` and `src/background.js`, and wire a provider selector + live Gemini Nano availability badge in `src/options/options.html` and `src/options/settings-database.js`. Users on Chrome 138+ with Gemini Nano available can enable `aiRatings` with zero API key and zero `openrouter.ai` host permission.
  - Keep `manifest.json` free of the expired `"aiLanguageModelOriginTrial"` permission.

### 6. `chrome.storage.sync` Stale Device-Chunk Pruning (Hardening)
- **Context:** `_syncVersion === 3` writes device-prefixed chunk keys (`icBackupAvoid_<device>_<bank>_<i>`). Across reinstalls or browser rotations, orphaned keys can accumulate toward the `102,400`-byte `chrome.storage.sync` limit.
- **Fix:** In `backupToChrome()` (`src/background.js`), after committing `icBackup`, inspect sync keys (via `getKeys()` when available or `get(null)`) and remove any `icBackupAvoid*` keys not belonging to the active committed `(device, bank, parts)` set.

### 7. Google Apps Script Backend Hardening & Scaling (`docs/apps-script.gs`)
- **Atomic USDA budget reservation:** Acquire `LockService.getScriptLock().tryLock(2000)` only for the `usdaBudget:<hour>` read-compare-increment, release immediately, then perform `UrlFetchApp.fetch()` outside the lock ([Apps Script Quotas](https://developers.google.com/apps-script/guides/services/quotas), [LockService](https://developers.google.com/apps-script/reference/lock/lock-service)).
- **Indexed `products` updates & `CacheService` lookup cache:** Cache hit rows in `CacheService.getScriptCache()` (`prod:<key>`, 600s TTL) inside `lookupProducts()`, update/invalidate them in `writeProducts()` and `purgeSharedProduct()`, and rewrite only modified rows + batch-append new rows in `writeProducts()` instead of rewriting the entire sheet on every batch.
- **Deployment observability:** Add `scriptRevision: '2026-11-21.1'` to `doGet` status JSON.

### 8. Exportable Shopping Shortlist (CSV) (Feature)
- **Design:** Add a formula-safe CSV export helper (`AIR.db.shopping.toCsv(rows, scoreFn)`) and an **Export shortlist (CSV)** button in `src/options/library.html` + `src/options/library.js`, respecting the active `#listFilter` and sanitizing leading `=`, `+`, `-`, `@`, `\t`, `\r` cells against spreadsheet formula injection.

### 9. Documentation & Validation Refresh
- Update `docs/CURRENT-VALIDATION.md` for `1.28.0`, fix the broken `1.19.2` link, and publish `docs/releases/1.28.0.md`.
