# Installed-extension testing — September 5, 2026

This follow-up tested the unpacked extension in Chrome for Testing 148 on actual Amazon pages, using Chrome storage, content scripts, the service worker, and the offscreen OCR document. It did not use the HTML harness for the findings below.

## Fixed: pasted ingredients disappear when preferences change

1. Open `https://www.amazon.com/dp/B00LOAW7U6` with OCR and Open Food Facts off.
2. Paste `Milk, cane sugar, natural flavors` and score it. This is a test input, not a transcription of the product label.
3. Change the sugar weight in the extension settings.

Before: the panel discarded the manual input and returned to the empty paste form. Reproduced twice.

After: the panel retains the page-local input and recalculates with the new preferences. Changing sugar weight from 1 to 2 changes this test score from 34 to 25. Selecting the Milk warning adds the warning and keeps the score. Navigation clears the saved manual input so it cannot carry over to another product.

Screenshots from this session were not checked into the repo (the `evidence/2026-09-05/` links are gone). The behaviour is pinned in `tests/content-lifecycle.test.js`.

## Fixed: search badges return after the master switch is off

1. Enable automatic search scoring.
2. Open `https://www.amazon.com/s?k=organic+peanut+butter&i=grocery`.
3. Scroll to previously unseen results and wait for a pending `…` badge.
4. Turn the master switch off before the requests finish.

Before: the badges disappeared immediately, then three badges (`80`, `?`, `82`) appeared while the master switch was still off.

After: disabling the master switch aborts active requests, invalidates their responses, and prevents scheduled work from starting. The same live sequence left zero badges after the pending requests finished. Turning off badges or automatic scoring, changing preferences, and navigating also invalidate outdated work. Re-enabling can arm tiles again.

Screenshots from this session were not checked into the repo. The abort-on-pause contract is pinned in `tests/content-lifecycle.test.js`.

## Fixed: the development launcher repeatedly times out

The wrapper supplied a fixed debugging port while agent-browser expected Chrome to allocate one and publish `DevToolsActivePort`. The browser opened but the command hung and repeatedly restarted its page. Removing the fixed port lets agent-browser manage its own connection.

Verified with a fresh isolated profile: the normal `scripts/ab.mjs` wrapper opened Chrome with the extension loaded, returned successfully, and returned its dynamically allocated debugging URL. The extension appeared enabled in Chrome's extension manager.

## Fixed: reload does not reload a sleeping extension

The reload helper only searched running service workers. Once Chrome suspended the worker, it reported `reloaded page (extension worker not found)` and left extension code unchanged.

A fallback now opens a temporary extension-manager tab, identifies the unpacked extension by its exact directory, clicks its reload control, and closes the temporary tab. Repeating the command with no worker target returned `reloaded extension and page`.
