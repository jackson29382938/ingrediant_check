# Ingredient Check codebase audit

**Baseline** `81a602a`, published as 1.28.2. **Target release** 1.29.0.

The second pass traced the extension from its manifest and message routes through label
extraction, scoring, retailer queues, saved evidence, and the extension pages. It also
reviewed Chrome and Google backup behavior, the Apps Script receiver and its sheet writes,
packaging checks, browser fixtures, and the outstanding proposals in the
[November 21 audit](AUDIT-2026-11-21.md).

## Findings and implemented changes

| Area | Finding on 1.28.2 | Change |
| --- | --- | --- |
| Allergen evidence | Inline retailer advisories could swallow the preceding ingredient list. Flattened or joined declarations could blur a direct declaration and a cross-contact statement. | Keep ingredients and advisories distinct during extraction and scoring. Preserve separators needed to identify the type of warning. |
| Saved label replay | Flattening photo line breaks changed the parsed recipe or advisory on replay. | Preserve bounded label and advisory line breaks in the product cache and retain warnings from both sources. |
| Nutrition and quantities | Inline nutrition text omitted total fat and split some grouped calorie and energy values. Decimal commas and alternate punctuation could hide small ingredient quantities. | Carry total fat through serving plausibility checks, retain grouped energy values, and normalize trace quantity markers. |
| Retailer traffic | Badge rating and explicit sorting could issue the same public product read or exceed their intended combined concurrency. | Use the same paced, bounded product queue and let a sort attach to an in-flight read. Cancel a sort without dropping separate badge work. |
| Sorted run lifecycle | Resetting a search or changing a setting could abandon a run while its view still showed loading. | Finalize canceled runs through the worker with source-tab and run checks. Keep partial results and reject later updates to that run. |
| Popup comparison | The swap callout referenced an unloaded module. Cache validation also missed AI and USDA switches. | Load the ranking dependencies, verify the current storefront and candidate evidence, and refresh on source changes. |
| Library comparison | Source gates and cache age were applied inconsistently, and a new search snapshot could leave the comparison price view stale. | Use current source preferences and the configured freshness window. Pair a cached score with evidence from its own source. Refresh the per-unit price view with the active search context and let the comparison table receive keyboard focus. |
| Shortlists | A CSV formatter existed without an export action. It could emit a numeric score from an unreadable label. | Connect a filtered export. Protect formula-leading fields and leave unassessed scores blank. Keep the full JSON export available. |
| Backup reliability | A device could republish an identical complete Chrome snapshot. Completion of an older save could clear a newer Chrome or Google fallback alarm. | Reuse identical complete copies and guard queued writes and alarm cleanup by generation. |
| Apps Script writes | A product write rewrote the whole sheet. A batched append could fail at the grid boundary. The status endpoint had no deployment revision. | Read product keys and the rows touched by the update, batch contiguous writes and new rows, grow sheet grids for appends, and expose the revision. |
| Packaging | Preflight only resolved the offscreen HTML page's script references. | Resolve scripts and stylesheet references on all packaged extension pages. |
| Retailer validation | The live probe could miss current Instacart product route shapes. | Recognize and match both the store-item and product paths. |

## New label-checking option

**Check with on-device AI** lets a shopper explicitly request a bounded classification of
unfamiliar ingredient names from a reviewed Library label. The extension page starts model
creation from the button gesture. It uses Chrome's Prompt API when available and applies the
same closed classification rules as the existing scorer. The regular check remains available.
An explicitly saved label retains its validated estimates for replay.

The earlier proposal placed Gemini Nano in a service worker. Chrome's documentation excludes
Web Workers from the Prompt API and requires user activation to start the download. The
extension-page implementation keeps this action separate from automatic retailer rating and
the existing OpenRouter switches. [Chrome Prompt API documentation](https://developer.chrome.com/docs/ai/prompt-api)

## Operational decisions

- Chrome sync can deliver writes from multiple devices out of order. Backup deduplication
  reduces new duplicate chunks without globally deleting chunks another device may still
  need. Divergent backups can still consume sync quota.
- An unversioned shared-product read cache could return purged or superseded rows. The
  receiver uses smaller reads and writes without introducing a second copy of those rows.
- The Apps Script changes apply to the checked-in template. Real sheet latencies, a live
  deployment, and authenticated Google sync require service-side verification.
- Platform API availability, structured response handling, and the extension Library flow
  have regression coverage. A real Gemini Nano download and model accuracy require a
  supported Chrome installation.
- The [validation record](CURRENT-VALIDATION.md) gives the automated and live evidence used for
  this release. Store fixtures are separate from the earlier signed-out retail spot check.
