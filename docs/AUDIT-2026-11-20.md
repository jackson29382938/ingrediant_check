## New findings

### P1 — Walmart requests product pages after automatic rating is turned off

Walmart opts into `alwaysRateSearch` and `publicCredentials: 'same-origin'` in
[src/stores/walmart.js](../src/stores/walmart.js#L305). The runner forces badges and automatic
rating on, and removes the normal speed cap. Search product requests can include Walmart's
same-origin cookies. The master pause still stops rating, and concurrency remains capped at two.
See [runner settings](../src/content/retailer.js#L41) and [request options](../src/content/retailer.js#L338).

This behavior is intentional according to the release notes and store guide. The privacy guide
makes a broader promise that turning automatic rating off uses saved scores only and that preview
requests omit cookies and stay within 20–60 requests. It later discloses Walmart cookies in its
sorting section. All 29 retailer-search fixture tests passed, including tests that explicitly
expect an uncached request with both switches off, 65 requests beyond the default allowance, and
same-origin credentials for an adapter that opts in. No signed-in Walmart traffic was used.
See [tests](../tests/retailer-search.test.js#L126), [privacy guide](PRIVACY.md#L49) and
[1.20.1 release notes](releases/1.20.1.md).

Make the global automatic-rating off switch stop Walmart's uncached reads. If the store needs a
separate control for session-based fetches, present that choice before sending them and describe
the limit. Keep sponsored-card handling independent so shoppers can still hide those cards.

### P2 — AI-transcribed photos are presented as product-page evidence

The Amazon fallback tags OpenRouter transcriptions `label-ai` with a fixed confidence of 0.5.
The panel's source formatter falls through to “Ingredients read from page (50% confidence)” and the
shopping evidence formatter emits “Product page.” Calling the shipped evidence formatter on
`label-ai` reproduced that wording locally. The label model was not called for this check.
See [photo fallback](../src/content/product.js#L523),
[panel source formatter](../src/content/panel.js#L238) and
[shopping evidence](../src/engine/db/shopping.js#L41).

Show “AI transcription of a product photo” in the panel and on saved and compared evidence.
Avoid presenting the fixed fallback value as measured confidence. Include all source types in a
table-driven formatting check so the same stored value has consistent wording across views.

### P2 — Two saves at the shortlist limit can succeed while one entry disappears from view

Starting with 199 saved items, two concurrent calls to the shipped `save()` both succeeded in a
local storage double. Storage contained 201 entries and `list()` returned 200, omitting the
second new item. Each save counts separately before writing. The listing also caps keys before
sorting the records, so the currently displayed set depends on key order.
See [shortlist storage](../src/engine/db/shopping.js#L77).

Serialize cap checks and writes through one writer shared by Library and product tabs. Read all
stored shortlist entries before ordering them and allow existing overflow to be recovered. Report
the limit explicitly in the save UI and test saves from separate views.

## Prior findings and priorities

The earlier audit's nine findings still apply to this commit. The most urgent are queued
OpenRouter requests after disabling AI or removing the API key, and OCR missing a selected soy
warning on a package that the recognizer rated 91% confident. The upload UI also scored a
garbled French label 65 versus 27 for a manual transcription. The earlier report records the
OCR boundary errors, sorted-list tooltip race, misleading validation results, old USDA record
dates, non-atomic quota accounting in the checked-in Apps Script, and keyboard access to the
purchase history table. See the [detailed findings](AUDIT-2026-11-16.md#findings).

Prioritize the two consent problems and the missed allergen. Then tighten photo acceptance and
source labeling, protect shortlist persistence and finish the tooltip and keyboard fixes. Refresh
the stale current-validation page as part of the next release.
